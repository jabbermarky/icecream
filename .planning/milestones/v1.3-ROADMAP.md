# v1.3 Ingredient Persistence - Milestone Archive

**Shipped:** 2026-01-15
**Phases:** 16-18 (3 phases, 3 plans)
**Git Range:** v1.2..v1.3

## Milestone Goal

Persist master ingredient list in IndexedDB so custom ingredients survive browser sessions.

## Accomplishments

### Phase 16: ingredient-storage
- Extended IndexedDB from v1 to v2 with new `ingredients` object store
- Added ingredient storage methods (saveIngredients, loadIngredients, hasIngredients)
- Implemented library-first loading pattern on app startup
- First run automatically bootstraps library from JSON defaults

### Phase 17: ingredient-sync
- Added fire-and-forget sync pattern for non-blocking storage updates
- Covered all 4 ingredient modification points with sync calls:
  - Edit ingredient name or property
  - Delete ingredient
  - Import from file or USDA
  - Store recipe as ingredient
- Added automated tests for sync and persistence

### Phase 18: recipe-ingredient-merge
- Extended importIngredients with configurable dialog labels
- Added columnLabels parameter for column headers (Library/Recipe)
- Added buttonLabels parameter for action buttons (Keep Library/Use Recipe)
- Recipe loading now clearly communicates library vs recipe values

## Key Decisions

| Decision | Rationale |
|----------|-----------|
| Single 'library' record for ingredients | Simpler than individual records, sufficient for current needs |
| Storage-first initialization | Enable library-first loading pattern |
| Fire-and-forget sync (no await) | Don't block user workflow for storage operations |
| Export sync function for recipe-manager | Allow cross-module sync when storing recipe as ingredient |
| columnLabels/buttonLabels parameters | Configurable dialog labels via parameter objects with defaults |
