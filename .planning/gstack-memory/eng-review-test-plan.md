## Affected Pages/Routes

- **Ingredients List tab** — the 🌐 download button per ingredient row. Every
  change in this plan is reachable from here. Test both a name USDA has
  (e.g. "whole milk") and one it does not (e.g. "pistachio paste").
- **Tools tab → PAC & POD calculator** — shares the derivation being extracted.
  Must produce the same numbers after the refactor as before it. This is the
  cross-check the user relies on, so a silent change here is worse than a bug.
- **Ingredients List → merge/confirm dialog** — where imported values are
  accepted or rejected before entering the library.

## Key Interactions to Verify

- Type a new ingredient name, click 🌐, choose from the result list, confirm the
  merge. PAC and POD should now be populated where previously they were not.
- Import an ingredient whose USDA record lacks galactose and maltose. Values
  must be populated and marked **measured**, not estimated.
- Import an ingredient whose record lacks a major sugar (sucrose, glucose,
  fructose, lactose) but reports total sugar. Values must be populated and
  marked **estimated**, with the assumption stated.
- Open the PAC/POD calculator, enter a known sugar mix, and compare its output
  against an import of the same profile. They must agree.
- Re-import an ingredient that already exists. The merge screen must show only
  real differences, not spurious ones caused by zero-handling.

## Edge Cases

- USDA record with a complete sugar profile (the current happy path) — must be
  unchanged, still marked measured.
- Record with no sugar breakdown at all but total sugar > 0. **Behavior
  undecided — see open decision in the review.**
- Record with total sugar of 0 (e.g. cream, egg yolk). Must not divide by zero
  or apportion a remainder that does not exist.
- Search returning fewer candidates than the ranking cutoff.
- Search returning only Foundation records, or none at all.
- Query with no results, triggering the truncate-and-retry path, ending in
  "no data found".
- Rate limit (HTTP 429), rejected key (403), server error (5xx), and network
  failure. Each must produce a distinct, actionable message — and all four must
  be distinguishable from "USDA has no data for this".
- Ingredient with no provenance sidecar (every existing entry) must load and
  read as `manual` without error.

## Critical Paths

- **REGRESSION (critical):** an ingredient whose USDA record has a complete
  sugar profile must derive exactly the same PAC and POD after the change as
  before it. This proves the tiered logic did not disturb the working path.
- **REGRESSION (critical):** `data/ingredients.json` must load unchanged, with
  no migration step and no diff noise, after the provenance sidecar is added.
- **End to end:** unknown ingredient → search → select → values populate →
  measured/estimated marker visible → accept merge → save → reload → values and
  provenance both persist.
- **Cross-surface consistency:** the extracted derivation must produce matching
  results in both the importer and the PAC/POD calculator, accounting for the
  100× unit-scale difference between them.
