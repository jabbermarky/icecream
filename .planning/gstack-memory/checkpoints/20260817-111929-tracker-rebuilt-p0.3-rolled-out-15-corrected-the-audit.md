### Decisions Made

**`.planning/` is agent memory; the GitHub Project is human-readable state.**
The maintainer pushed back hard on my assessment that the existing record was
"unusually good" — it is, but only for a reader who arrives with no memory and
reads everything. That reader is Claude, not them. The sprawl across many
markdown files is exactly why they could not see what was happening. Different
readers, not duplicates. Consequence: issue bodies are written LONG on purpose,
carrying reasoning inline, so the board is readable without opening a design doc.

**Status lives in the tracker; nothing duplicates it.** 8 labels, all covering
KIND of work (`batch-loop`, `phase-0`, `sync`, `ingredients`, `binder-audit`,
`deploy`, `security`) plus one type label per issue and `data-loss` as the single
cross-cutting severity marker. No `blocked` or `redesign` label, because Status
already carries those and a second place to update is a second place to drift.

**Milestones = what ships together, and contain their own blockers.** Split at
the maintainer's request into 1 hosting (#40), 2 the loop closes (#39 + #41's
five children), 3 the diff (#30, #36, #16), 4 guardrails (#15 done, #17 left).
No due dates — an invented date makes a permanently-overdue milestone. Absence of
a milestone means not-yet-committed, which is the field carrying information.

**Reversed my own call on retro-filing.** I argued against creating closed issues
for finished Phase 0 work as tracker rot. That was right when it bought nothing;
milestones made it buy honest bars and a visible Done column. #42–#45 filed and
closed.

**#15 went the opposite way from the issue.** `(220 - 230)` was never the type's
range. There is no per-type PAC range anywhere in the codebase — `cTarget`
carries Fat, MSNF, Solids, POD, Stabilizer and never PAC. The band was the
upstream author's gelato numbers, inherited verbatim from `IceEd.html:1743` and
compared to nothing. Fix: POD uses the per-type range that already existed
(×1000 to the display scale; NO type is 110–120), PAC uses the derived
`GetIdealPAC` ideal, which turned out to be type-sensitive via
`Target.MSNF.Mean`. Out-of-range shows as a WORD not a colour, because the block
prints on the churn sheet and colour is the first thing a mono printer drops.

**#16 is not ahead of the queue.** I proposed building it, the maintainer caught
that it is batch-loop work. My own milestone assignment already put it in
milestone 3. The audit's grounds for jumping it ahead — "~an hour each, either
would have caught the regression" — expired: the estimate was a guess (it is 2–3
hours; the container is rebuilt every save so lineage must be carried forward
explicitly through module state), and #15 turned out to be measured against a
fiction so only one guardrail ever applied.
