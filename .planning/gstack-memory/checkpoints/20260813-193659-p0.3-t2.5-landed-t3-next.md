### Decisions Made

- **Decision 6 AMENDED (cross-model KEEP verdict, maintainer-confirmed): a
  save mints when keeping the id would put it on two local records;
  otherwise identity follows the recipe.** The original "different-id
  overwrite is a copy and mints" letter was about the rename flow and
  over-reached: minting on the import-collision case would disconnect batch
  history (P0.4 hangs on ids) and make the id-first sync join manufacture
  duplicates. Both codex and Claude independently recommended KEEP. Honest
  cost recorded: the id a save produces depends on a local scan.
- **Decision 11 implemented at import time:** a file whose id already lives
  in the library prompts "same recipe as X — load AS that recipe, or as an
  independent copy?" Cancel adopts null (mints at next save). One shared
  scanForIdentityCarrier serves both this prompt and the mint decision.
- **The strong overwrite prompt now fires on targetId alone differing** —
  an UNIDENTIFIED recipe destroying an identified one was getting the weak
  prompt (codex 1a).
- **Identity travels through the backup stack** (codex 7): restore returns
  the backed-up id; the old behavior could cross-assign an imported
  recipe's id to a restored backup.
- **containerSavedAt requires ISO shape** before Date.parse (codex 10 —
  non-ISO parsing is implementation-dependent, cross-runtime merge
  divergence).
- **T3/T4 spec grew:** the join module must ALSO gate pushRecipe (codex 3 —
  fire-and-forget second write path bypasses the join; its false-success
  half is #12). "Known windows until T3/T4" recorded in the design doc:
  local-only scan, overwrite TOCTOU (item 20 family), loadRecipe
  not-found/error conflation (#12 family).
- **Rejected from the codex round, deliberately:** loose id validation
  (T1-review decision — hand-authored .ier files are legal; only
  trim/length matter to the string-equality join).
- **Review cadence settled:** light built-in /code-review (low/medium) for
  contained steps; full gstack /review for trust-boundary steps (T4) and
  once over the whole diff at the merge boundary. The fresh-context outside
  voice is the highest-value pass; codex now available again for it.
- **PR cadence settled:** docs PRs merge immediately (#5 done); #11 merges
  at the END of P0.3 (after T6), then closes — P0.4+ gets a fresh branch
  and PR. Merge ≠ deploy: the reload-every-device ritual attaches to
  deploy.
