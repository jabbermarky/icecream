<task type="auto">
  <name>Task 1: Clear sortBy when user drag-reorders</name>
  <files>js/features/recipe-manager.js</files>
  <action>
In the `onDrop()` function (around line 586), after reordering `Recipe.Ingredients` array and before calling `SetRecipeModified()`, clear the sort state so the column header no longer shows a misleading sort indicator.

Add this line:
```javascript
sortBy = null;
```

Then call `DisplayRecipe()` to refresh the header (which will no longer show ▲/▼ since sortBy is null).

Wait - calling DisplayRecipe() would rebuild the entire table, losing the drag result. Instead, we need to just update the header.

Better approach: After clearing sortBy, find the header cell that has the sort indicator and remove just the indicator span. The sort indicator is added in DisplayRecipe() as:
```javascript
if (columnName === sortBy)
    cell.innerHTML += '<span class="noprint">' + (sortAsc ? " \u25B2" : " \u25BC") + '</span>';
```

So in onDrop, after setting sortBy = null, remove any existing sort indicator spans from the header:
```javascript
// Clear sort indicator from header
const header = document.querySelector('#tblRecipe thead tr');
header.querySelectorAll('th span.noprint').forEach(span => {
    if (span.textContent.includes('▲') || span.textContent.includes('▼')) {
        span.remove();
    }
});
```
  </action>
  <verify>

3. Drag an ingredient to a different position
4. Verify the sort indicator (▲/▼) disappears from the header
5. `npm test` passes
  </verify>
  <done>Sort indicator disappears when user manually reorders via drag-drop. Tests pass.</done>
</task>

  <action>
Add a new test method `testOrderPersistence()` that:

1. Loads a recipe with known ingredient order
2. Records the original ingredient order (array of names)
3. Simulates drag-drop to reorder (move first ingredient to third position)
4. Saves the recipe to a file
5. Creates a new recipe (clears current)
6. Loads the saved file
7. Verifies ingredients are in the reordered order

Note: Playwright doesn't have built-in drag-drop simulation for HTML5 drag-drop, but we can use `page.dispatchEvent()` or `page.evaluate()` to programmatically trigger the reorder by directly manipulating the Recipe.Ingredients array and calling DisplayRecipe() - this tests the persistence, not the drag UI (which is already tested manually in Phase 10 UAT).

Alternative approach: Since the drag-drop reorder ultimately just reorders the Recipe.Ingredients array and calls DisplayRecipe(), we can:
1. Load recipe
2. Use page.evaluate() to reorder Recipe.Ingredients programmatically
3. Save
4. New recipe
5. Load saved file
6. Check order matches reordered order

This tests that order persists through save/load cycle without needing complex drag simulation.

Add the test to the TestSuite class and add it to the test list in `runTests()`.
